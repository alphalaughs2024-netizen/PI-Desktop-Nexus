# 0.15.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a versioned 0.15.0 Windows installer and portable executable for PI Desktop Nexus.

**Architecture:** The release is a version-surface-only change: changelog records the user-visible work already present on local `main`, the release script synchronizes package and native version metadata, and GitHub Release assets are built from the tagged commit. No runtime interface or product behavior changes are introduced by this release operation.

**Tech Stack:** Node.js release scripts, TypeScript changelog catalog, Cargo workspace metadata, pnpm, Electron Builder, GitHub CLI.

**Spec:** `docs/spec/06-delivery/06-release-runbook.md` section 4.1.

## Global Constraints

- All version-bearing workspace package manifests, Cargo metadata, protocol metadata, changelogs, changelog test, and English/Chinese README release lines must state `0.15.0` / `0.15.x`.
- Every shipped changelog locale must contain a newest-first `0.15.0` entry with the same highlight count as English.
- The release tag must identify the precise commit used for the installer assets.
- Windows artifacts must be built with `pnpm --filter @pi-desktop/desktop run dist:win` and checked before upload.

### Task 2: Synchronize metadata, package, and publish

**Files:**
- Modify: workspace `package.json` files, `Cargo.toml`, `Cargo.lock`, `packages/shared/src/protocol.ts`, and `apps/desktop/resources/models.dev/api.json` through `scripts/release.mjs`

**Interfaces:**
- Consumes: the validated release-surface documentation from Task 1.
- Produces: tag `v0.15.0` pointing at the commit whose package metadata and uploaded installers identify `0.15.0`.

- [ ] **Step 1: Run the release synchronizer**

Run: `node scripts/release.mjs 0.15.0`

Expected: every required metadata surface is updated and the release preflight passes.

- [ ] **Step 2: Commit and tag the release source**

Run: `git add -A && git commit -m "chore(release): v0.15.0" && git tag v0.15.0`

Expected: a clean worktree and a local `v0.15.0` tag at the release commit.

- [ ] **Step 3: Build and verify release assets**

Run: `pnpm install --frozen-lockfile && pnpm --filter @pi-desktop/desktop run dist:win`

Expected: `PI-Desktop-Nexus-Setup-0.15.0.exe` and `PI-Desktop-Nexus-Portable-0.15.0.exe` exist in `apps/desktop/release/`.

- [ ] **Step 4: Publish the GitHub release**

Run: `git push nexus HEAD:main v0.15.0 && gh release create v0.15.0 --repo alphalaughs2024-netizen/PI-Desktop-Nexus --title "PI Desktop Nexus 0.15.0" --generate-notes apps/desktop/release/PI-Desktop-Nexus-Setup-0.15.0.exe apps/desktop/release/PI-Desktop-Nexus-Portable-0.15.0.exe`

Expected: a published GitHub release for `v0.15.0` containing both Windows artifacts.

# ADR 0279: Nexus identity and execution bindings

- Status: Accepted

## Decision

Use a shared Nexus identity in the custom model template and session developer
instructions. The engine executes Nexus's capabilities rather than presenting
a separate assistant. Preserve honest answers to explicit engine/model questions,
technical diagnostics, tool names and provider identifiers. Apply the same
instructions to resumed sessions, mode transitions and configured delegates.
No generated-text scrubbing or fabricated capability promises are introduced.

Advertise Browser from actual catalog/grants and managed previews from the
complete permitted service set. Reuse the existing cancellable native-item
binding wait for Plan transitions, matching Task delivery across independent
channels. Preserve exact host turn ownership and policy enforcement.

Reject invalid native approval decisions before consuming a request and reject
invalid sandbox modes before mapping them. Bind approval argument previews to
linked file-change and command evidence. Native escalation remains once-only;
scoped session grants are a separate future request. No storage/schema migration
or additional execution engine is introduced.
